# Day 16. 프롬프트 엔지니어링

> 작성일: 2026-08-04

## 📝 오늘 배운 내용 요약
1. **프롬프트를 AI에게 전달하는 업무 지시서로 이해했다**
  - 좋은 프롬프트는 단순히 길게 쓰는 것이 아니라 목적, 맥락, 입력, 진행 방법, 출력 형식과 제약조건을 빠뜨리지 않고 전달하는 것이 중요하다.
  - 같은 입력 자료라도 대상과 목적, 결과 형식을 다르게 지정하면 요약문, 체크리스트, 표와 면접 질문처럼 서로 다른 결과물을 만들 수 있다.
  - 반복 업무에서는 프롬프트의 구조를 템플릿으로 만들어두면 결과의 일관성과 재사용성을 높일 수 있다.
2. **Zero-shot, One-shot과 Few-shot Prompting의 차이를 학습했다**
  - Zero-shot은 정답 예시 없이 작업을 요청하는 방식으로, 일반적인 요약이나 번역처럼 기준이 명확한 작업에 적합하다.
  - One-shot은 하나의 완성 예시를 제공하여 출력 항목, 순서와 문체를 빠르게 전달하는 방식이다.
  - Few-shot은 여러 예시를 통해 분류 기준, 예외 처리와 내부 규칙까지 전달하며, 현재 대화 안에서 패턴을 적용하는 In-context Learning으로 이해할 수 있다.
  - 예시의 수보다 대표 사례, 다양한 표현, 경계 사례와 반례를 일관된 기준으로 고르는 것이 더 중요하다.
3. **단계적 사고와 출력 형식 지정의 필요성을 이해했다**
  - 복잡한 문제는 바로 결론을 요구하기보다 필요한 하위 작업과 판단 기준을 단계별로 나누면 누락을 줄일 수 있다.
  - 표, 체크리스트, JSON과 정해진 항목처럼 출력 형식을 명확히 지정하면 결과를 후속 작업이나 프로그램에서 활용하기 쉬워진다.
  - 사실, 추정과 확인 불가 정보를 구분하도록 요구하면 결과를 검토하기 쉬워지고 잘못된 단정을 줄일 수 있다.
4. **Hallucination 완화와 안전한 프롬프트 설계를 학습했다**
  - Hallucination은 AI가 확인되지 않은 정보를 그럴듯하게 생성하는 현상이며, 입력 부족, 모호한 질문, 최신 정보 요청과 충돌하는 자료에서 발생하기 쉽다.
  - 제공된 자료만 사용하도록 범위를 제한하고, 근거를 표시하며, 자료에 없는 내용은 확인 불가로 답하게 하는 Grounding 원칙을 적용해야 한다.
  - System Prompt는 역할과 기본 규칙을 설정하지만 완전한 보안 장치는 아니며, Prompt Injection과 Jailbreak를 고려한 입력·출력 검증 및 권한 제한이 함께 필요하다.
## 💭 오늘의 회고
1. **배운 점**
  - 프롬프트 작성은 질문을 길게 만드는 기술이 아니라, 원하는 작업의 기준과 검증 가능한 결과 형식을 설계하는 과정임을 이해했다.
  - 예시와 제약조건을 적절히 제공하면 모델을 다시 학습하지 않아도 특정 업무 규칙을 현재 대화 안에서 반영할 수 있다는 점을 배웠다.
  - AI의 자연스러운 문장과 사실의 정확성은 별개의 문제이므로 근거와 불확실성을 함께 확인해야 한다.
2. **어려운 점/개선할 점**
  - 복잡한 요청에서 목적, 진행 방법과 제약조건을 어디까지 구체화해야 하는지 판단하기 어려웠다.
  - Few-shot 예시가 많아질수록 서로 충돌하거나 불필요한 패턴까지 전달할 수 있어 좋은 예시를 선별하는 연습이 필요하다.
  - System Prompt만으로 보안을 해결할 수 없으므로 Prompt Injection에 대응하는 전체 시스템 구조를 추가로 학습할 필요가 있다.
3. **액션 플랜**
  - 자주 사용하는 요청 하나를 선택해 목적, 맥락, 입력, 진행 방법, 출력 형식과 제약조건으로 나누어 재사용 가능한 템플릿을 만든다.
  - 동일한 분류 작업을 Zero-shot, One-shot과 Few-shot으로 실행해 결과의 일관성과 정확도를 비교한다.
  - 답변에 사실, 추정, 확인 불가와 근거 항목을 포함시켜 Hallucination을 줄이는 프롬프트를 실험한다.
4. **함께 나누고 싶은 점**
  - AI가 자신 있게 답한다고 해서 정확한 것은 아니므로, 중요한 업무에서는 출처와 근거를 확인하는 과정이 반드시 필요하다.
