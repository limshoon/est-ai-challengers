# Day 17. RAG 시스템 구축

> 작성일: 2026-08-05

## 📝 오늘 배운 내용 요약
1. **RAG의 필요성과 전체 구조를 학습했다**
  - LLM은 학습 시점 이후의 정보나 회사 내부 문서와 같은 사적 정보를 알 수 없고, 모르는 내용도 그럴듯하게 생성할 수 있다.
  - RAG는 사용자 질문과 관련된 문서를 검색하고, 검색 결과를 참고 자료로 추가한 뒤 LLM이 답변을 생성하는 Retrieval, Augmentation, Generation 구조이다.
  - 모델 자체를 다시 학습하는 Fine-tuning과 달리 RAG는 문서를 추가하거나 교체하여 새로운 지식을 반영할 수 있다.
  - 검색된 문서가 부정확하면 생성 결과도 잘못될 수 있으므로 RAG의 성능은 검색 품질에 크게 좌우된다.
2. **임베딩을 이용한 의미 기반 검색을 실습했다**
  - 단어가 겹치는지만 비교하는 검색은 동의어나 서로 다른 표현을 처리하기 어렵지만, 임베딩은 문장의 의미를 벡터로 표현해 의미적으로 가까운 문서를 찾을 수 있다.
  - 질문과 문서를 같은 임베딩 모델로 변환한 뒤 코사인 유사도를 계산하여 관련 문서를 선택한다.
  - 실제 RAG에서는 가장 가까운 문서 하나만 고르기보다 Top-K 검색을 통해 여러 관련 문서를 함께 참고 자료로 제공한다.
  - 문서 임베딩은 미리 계산해 저장하고, 질문이 들어올 때 질문만 임베딩하는 방식이 효율적이다.
3. **Vector DB와 FAISS의 역할을 이해했다**
  - 문서 수가 많아지면 모든 벡터를 반복문으로 비교하는 방식은 느려지므로, 유사한 벡터를 빠르게 검색하는 Vector DB가 필요하다.
  - FAISS는 임베딩 벡터를 인덱스에 등록하고 가까운 벡터를 효율적으로 찾는 무료 오픈소스 라이브러리이다.
  - FAISS의 L2 거리는 값이 작을수록 유사하고, 코사인 유사도는 값이 클수록 유사하므로 결과의 방향을 구분해야 한다.
  - 문서 원문과 벡터 인덱스의 순서를 일치시키고, 벡터 자료형을 float32로 맞추는 것이 중요하다.
4. **Chunking과 LangChain으로 RAG 파이프라인을 구성했다**
  - 긴 문서를 하나의 벡터로 만들면 세부 정보가 희석되고, 너무 작게 나누면 문맥이 끊기므로 적절한 크기로 문서를 나누는 Chunking이 필요하다.
  - 고정 길이, 문장 단위와 Overlap 방식의 차이를 비교했으며, 문서 구조와 질문의 특성에 맞는 청크 크기를 선택해야 한다.
  - LangChain은 문서 로드, 분할, 임베딩, 저장, 검색과 생성을 표준화된 구성요소로 연결하는 프레임워크이다.
  - RecursiveCharacterTextSplitter, HuggingFace Embeddings, FAISS와 RetrievalQA를 연결해 전체 RAG 흐름을 구성할 수 있다.
## 💭 오늘의 회고
1. **배운 점**
  - RAG는 LLM에 지식을 새로 학습시키는 방법이 아니라, 질문마다 필요한 자료를 검색해 프롬프트에 추가하는 방법임을 이해했다.
  - 임베딩, Vector DB와 Chunking은 별개의 기능이 아니라 정확한 문서를 찾기 위해 이어지는 하나의 검색 파이프라인이라는 점을 배웠다.
  - 좋은 생성 모델만 선택하는 것보다 어떤 문서를 어떤 단위로 검색해 전달하는지가 결과 품질에 큰 영향을 준다.
2. **어려운 점/개선할 점**
  - 청크 크기와 Overlap을 어느 정도로 설정해야 가장 좋은지 정답이 고정되어 있지 않아 실험적인 비교가 필요했다.
  - 코사인 유사도와 L2 거리의 계산 방식 및 결과 해석 방향을 혼동하지 않도록 정리할 필요가 있다.
  - LangChain이 많은 과정을 자동화하므로 내부에서 어떤 단계가 실행되는지 놓치기 쉬웠다.
3. **액션 플랜**
  - 짧은 개인 문서를 여러 청크 크기로 나누고 동일한 질문의 검색 결과와 유사도 점수를 비교한다.
  - SentenceTransformer로 문서와 질문을 임베딩한 뒤 FAISS에 등록하고 Top-K 검색까지 직접 구현한다.
  - 직접 만든 RAG 파이프라인과 LangChain으로 만든 파이프라인의 코드 구조 및 결과를 비교한다.
4. **함께 나누고 싶은 점**
  - RAG를 적용해도 Hallucination이 완전히 사라지는 것은 아니며, 검색 문서의 품질과 답변의 근거를 함께 검증해야 한다.
