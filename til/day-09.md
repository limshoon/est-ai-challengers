# Day 9. 특성 엔지니어링과 데이터 수집

> 작성일: 2026-07-24

## 📝 오늘 배운 내용 요약
1. **전처리 함수를 연결하고 범주형 데이터를 인코딩했다**
  - DataFrame의 모든 셀에 함수를 적용하는 `applymap()`과 행·열 단위로 동작하는 `apply()`의 차이를 이해했다.
  - `pipe()`를 사용하면 여러 전처리 함수를 위에서 아래 순서로 연결할 수 있어 중첩 호출보다 흐름이 명확하고 재사용하기 쉽다는 점을 배웠다.
  - Label Encoding은 순서가 있는 범주에, One-Hot Encoding은 순서가 없는 범주에 적합하다는 기준을 익혔다.
  - `pd.get_dummies()`와 `OneHotEncoder`를 사용하고, 학습 시 보지 못한 새로운 범주를 처리하는 방법도 고려해야 한다는 점을 배웠다.
2. **수치형 특성의 범위를 조정하는 스케일링을 학습했다**
  - `MinMaxScaler`는 값을 0\~1 범위로 변환하지만 이상치에 민감하다는 점을 배웠다.
  - `StandardScaler`는 평균 0, 표준편차 1로 표준화하며, `RobustScaler`는 중앙값과 IQR을 사용해 이상치에 비교적 강하다는 점을 이해했다.
  - 데이터 누수를 막기 위해 훈련 데이터에만 `fit()`하고, 테스트 데이터에는 동일한 기준으로 `transform()`만 적용해야 한다.
3. **웹크롤링의 기본 흐름과 윤리를 학습했다**
  - `requests.get()`으로 HTML을 가져오고 상태 코드가 200인지 확인한 뒤, `BeautifulSoup`으로 파싱했다.
  - `find()`, `find_all()`, `select_one()`, `select()`를 사용해 태그나 CSS 선택자로 원하는 정보를 추출했다.
  - 여러 페이지를 수집할 때 요청 간격을 두고, `robots.txt`, 이용약관, 개인정보와 저작권을 확인해야 한다는 점을 배웠다.
  - JavaScript로 동적으로 생성되는 페이지는 Selenium과 명시적 대기(`WebDriverWait`)를 활용할 수 있으며, 작업 후 브라우저를 종료해야 한다.
4. **OpenAPI와 JSON을 활용해 구조화된 데이터를 수집했다**
  - API는 정해진 규칙과 형식으로 데이터를 주고받는 통로이며, 공식 API가 있다면 크롤링보다 우선 사용하는 것이 안정적이라는 점을 이해했다.
  - `requests.get(url, params=...)`로 조건을 전달하고 `response.json()`으로 응답을 파이썬 객체로 변환했다.
  - 리스트와 딕셔너리 구조의 JSON은 `pd.DataFrame()`이나 `pd.json_normalize()`로 표 형태로 변환했다.
  - API 키는 코드에 직접 작성하지 않고 환경변수 등으로 분리해 관리해야 한다는 점을 배웠다.
5. **정규표현식과 XML 데이터 처리 방법을 익혔다**
  - 정규표현식은 이메일, 전화번호, 금액처럼 일정한 문자열 패턴을 검색하고 추출하는 문법이며 `search()`, `match()`, `findall()`, `sub()`를 활용했다.
  - 패턴 문자열 앞에 `r`을 붙여 이스케이프 문제를 줄이고, 크롤링한 텍스트에서 숫자나 특정 형식을 정제하는 데 활용했다.
  - XML은 태그 구조로 데이터를 표현하며 `ElementTree`의 `fromstring()`, `find()`, `findall()`로 파싱하고, 속성은 `.get()`, 텍스트는 `.text`로 읽었다.
6. **데이터 수집·정제 프로젝트와 머신러닝의 기본 개념을 연결했다**
  - 원본 데이터는 보존하고 복사본에서 작업하며, 출처·수집일·라이선스·데이터 범위를 기록해야 한다는 원칙을 배웠다.
  - 결측치, 중복, 이상한 수치와 범주를 진단하고, 무엇을 왜 어떻게 수정했는지 데이터 카드의 정제 로그로 남기는 방법을 익혔다.
  - 머신러닝은 지도학습, 비지도학습, 강화학습으로 나뉘며, 지도학습은 연속값을 예측하는 회귀와 범주를 예측하는 분류로 구분된다는 점을 학습했다.
## 💭 오늘의 회고
1. **배운 점**
  - 좋은 모델을 만들기 전에 신뢰할 수 있는 데이터를 수집하고 전처리 과정을 재현 가능하게 기록하는 것이 중요하다는 점을 배웠다.
  - 크롤링, API, JSON, XML은 형식이 다르지만 데이터를 안전하게 가져와 구조화된 표로 바꾸는 공통 흐름을 가진다는 점을 이해했다.
2. **어려운 점/개선할 점**
  - CSS 선택자와 정규표현식은 대상 페이지나 문자열 구조에 따라 달라져 반복 실습이 필요하다.
  - 인코딩과 스케일링을 데이터 분할 전에 적용하면 데이터 누수가 발생할 수 있으므로 처리 순서를 주의해야 한다.
3. **액션 플랜**
  - 허용된 연습 사이트 또는 공개 API에서 데이터를 수집해 DataFrame으로 변환하고 CSV로 저장한다.
  - 수집한 데이터의 출처, 품질 문제와 정제 내역을 데이터 카드 형식으로 기록한다.
4. **함께 나누고 싶은 점**
  - 수집 가능하다는 사실과 수집해도 된다는 사실은 다르므로 기술적 가능성뿐 아니라 사이트 정책과 윤리를 함께 확인해야 한다.
