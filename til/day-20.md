# Day 20. 온라인 해커톤 준비와 AI 서비스 기획

> 작성일: 2026-08-10

## 📝 오늘 배운 내용 요약
1. **온라인·오프라인 해커톤의 전체 진행 구조와 목표를 확인했다**
  - 이번 해커톤은 ESG와 사회문제 해결형 서비스를 주제로 진행되며, 단순한 아이디어 제안이 아니라 실제 사용자 문제를 정의하고 해결 방안을 서비스 형태로 구체화해야 한다.
  - 온라인 해커톤에서는 서비스 기획안과 발표 PPT를 완성하고, 이후 오프라인 해커톤에서는 작동 가능한 MVP와 시연 결과까지 발전시키는 구조임을 확인했다.
  - 제한된 시간 안에 모든 기능을 구현하기보다 핵심 문제와 핵심 기능을 명확히 정해 우선순위를 세우는 것이 중요하다.
2. **AI 기술보다 문제 정의가 먼저라는 점을 정리했다**
  - AI를 사용한다는 사실 자체보다 어떤 사용자의 어떤 불편을 해결하는지가 서비스 기획의 출발점이다.
  - 문제 상황, 대상 사용자, 기존 해결 방식의 한계와 기대 효과를 먼저 정리한 뒤 AI가 실제로 필요한 부분을 선택해야 한다.
  - 기능을 많이 넣기보다 사용자가 서비스를 이용하는 흐름과 AI가 개입하는 지점을 명확하게 설계해야 한다.
  - 발표에서도 기능 나열보다 문제 정의 → 해결 방법 → 기대 효과가 자연스럽게 이어지도록 구성하는 것이 중요하다.
3. **AI API를 서비스에 연결하는 기본 구조를 다시 정리했다**
  - API는 서로 다른 서비스나 프로그램이 정해진 형식으로 데이터를 주고받게 하는 연결 통로이다.
  - AI 기능을 실제 서비스에 적용할 때는 사용자 입력을 서버에서 처리하고, 필요한 데이터를 AI API에 전달한 뒤 결과를 다시 사용자에게 보여주는 흐름으로 구성할 수 있다.
  - 외부 AI API를 사용할 경우 모델 성능뿐 아니라 응답 속도, 사용 비용, 개인정보 처리, 호출 제한과 오류 상황도 함께 고려해야 한다.
  - AI Agent나 외부 API를 활용하면 직접 모델을 학습하지 않아도 필요한 AI 기능을 서비스에 빠르게 연결할 수 있다는 점을 이해했다.
4. **팀 프로젝트에서 역할 분담과 빠른 의사결정의 중요성을 확인했다**
  - 짧은 해커톤에서는 기획, UI/UX, 개발과 발표자료 제작을 동시에 진행해야 하므로 각자의 역할과 결과물을 명확히 정해야 한다.
  - 화면 디자인과 기능 구현을 별개의 작업으로 보지 않고, 실제 사용 흐름과 구현 가능성을 함께 확인하면서 설계해야 한다.
  - 완벽한 결과물을 만드는 것보다 핵심 기능이 실제로 동작하는 작은 범위의 결과물을 먼저 완성한 뒤 확장하는 방식이 효율적이다.
  - 멘토링을 통해 문제 정의와 기술 선택이 적절한지 빠르게 검증하고 피드백을 즉시 반영하는 과정도 중요하다.
## 💭 오늘의 회고
1. **배운 점**
  - 지금까지 배운 Python, 데이터 분석, 머신러닝, LLM과 AI Agent 관련 지식은 각각 분리된 기술이 아니라 실제 서비스를 구성하기 위한 여러 도구라는 점을 다시 느꼈다.
  - 해커톤에서는 기술적으로 가능한 것을 모두 구현하는 것보다 문제에 필요한 기술을 선택하고 제한된 시간 안에 완성하는 판단력이 중요하다.
  - 좋은 서비스 기획은 기능의 수보다 문제 정의와 사용자 흐름이 얼마나 명확한지에 의해 결정된다는 점을 배웠다.
2. **어려운 점/개선할 점**
  - 새로운 아이디어를 생각할 때 AI를 먼저 떠올리고 그에 맞는 문제를 찾으려는 경향이 있어 문제 중심으로 사고하는 연습이 더 필요하다.
  - 여러 API와 AI 기술 가운데 실제 프로젝트에 가장 적합한 방법을 선택하려면 각 기술의 장단점과 구현 난이도를 더 정확히 이해해야 한다.
  - 짧은 시간 안에 기획, 디자인과 개발의 범위를 동시에 조절하는 것이 어렵기 때문에 초기에 핵심 기능을 더 과감하게 제한할 필요가 있다.
3. **액션 플랜**
  - 해커톤 시작 전에 해결하려는 문제를 한 문장으로 정의하고, 대상 사용자와 핵심 불편을 명확하게 정리한다.
  - 전체 서비스 화면 흐름과 데이터 흐름을 간단하게 도식화해 디자인과 개발이 같은 구조를 공유하도록 한다.
  - AI 기능은 반드시 필요한 부분만 선정하고, 사용할 API의 입력·출력 형식과 구현 가능성을 먼저 테스트한다.
  - 기획안과 발표자료는 문제 정의 → 사용자 → 해결 방법 → 핵심 기능 → 기대 효과 순서로 정리한다.
4. **함께 나누고 싶은 점**
  - 해커톤에서는 좋은 기술을 많이 사용하는 것보다 명확한 문제를 선택하고 그 문제를 해결하는 데 필요한 기술만 사용하는 것이 더 중요하다고 생각했다.
