# Day 19. AI 윤리와 프로젝트 마무리

> 작성일: 2026-08-07

## 📝 오늘 배운 내용 요약
1. **AI Human 기술의 발전과 사회적 영향을 살펴보았다**
  - 생성형 AI는 텍스트와 이미지 생성에서 더 나아가 음성, 영상과 상호작용을 결합한 AI Human 형태로 확장되고 있다.
  - 사람과 유사한 표현과 반응을 제공할수록 정보 전달과 서비스 접근성은 높아질 수 있지만, 실제 인물과 AI를 혼동하게 만들 위험도 커진다.
  - 기술의 성능뿐 아니라 사용 목적, 대상과 공개 방식까지 함께 설계해야 한다.
2. **AI 서비스에서 고려해야 할 윤리 문제를 학습했다**
  - 학습 데이터와 생성 결과에는 저작권, 개인정보, 초상권과 데이터 이용 동의 문제가 포함될 수 있다.
  - 모델은 학습 데이터의 불균형과 사회적 편견을 반영해 특정 집단에 불리한 결과를 만들 수 있으므로 편향을 점검해야 한다.
  - AI가 만든 결과임을 명확히 알리고, 고위험 의사결정에서는 사람이 검토하고 책임지는 절차가 필요하다.
  - 데이터 수집 단계부터 필요한 정보만 사용하고, 민감정보를 제거하거나 보호하는 원칙을 적용해야 한다.
3. **Responsible AI와 AI 거버넌스의 필요성을 이해했다**
  - Responsible AI는 정확도뿐 아니라 공정성, 투명성, 설명 가능성, 개인정보 보호, 안전성과 책임성을 함께 고려하는 접근이다.
  - AI 거버넌스는 모델의 개발, 배포와 운영 과정에서 책임 주체와 검토 절차, 기록 및 대응 기준을 정하는 체계이다.
  - 문제가 발생한 뒤 수정하는 것보다 데이터 선택, 모델 평가, 사용자 안내와 모니터링을 개발 과정에 포함하는 것이 중요하다.
  - 실제 서비스에서는 사용 범위와 금지 용도, 사람의 승인 조건과 오류 신고 절차를 명확히 정해야 한다.
4. **프로젝트 결과를 정리하고 전체 학습 과정을 돌아보았다**
  - 프로젝트는 모델을 만드는 것만으로 끝나지 않으며, 해결하려는 문제와 데이터, 선택한 방법, 평가 결과와 한계를 함께 설명해야 한다.
  - 발표에서는 기능을 나열하기보다 왜 이 문제를 선택했고 어떤 근거로 해결 방법을 결정했는지 전달하는 것이 중요하다.
  - Python 기초부터 데이터 분석, 머신러닝, 딥러닝, LLM, RAG와 AI Agent까지의 학습 내용이 하나의 AI 서비스 개발 흐름으로 이어진다는 점을 확인했다.
  - 결과의 성능뿐 아니라 재현 가능성, 한계와 다음 개선 계획을 기록해야 프로젝트를 발전시킬 수 있다.
## 💭 오늘의 회고
1. **배운 점**
  - AI 기술은 구현 가능성만으로 평가할 수 없으며, 데이터의 권리와 사용자에게 미치는 영향까지 개발자가 책임 있게 검토해야 한다.
  - 편향과 Hallucination은 모델 사용 단계의 실수가 아니라 데이터, 모델과 시스템 설계 전반에서 관리해야 하는 문제임을 이해했다.
  - 프로젝트를 설명할 때 성공 결과뿐 아니라 판단 과정, 한계와 개선 방향을 함께 제시해야 학습과 문제 해결 역량이 드러난다.
2. **어려운 점/개선할 점**
  - 저작권과 개인정보처럼 기술 외적인 기준은 상황과 데이터 출처에 따라 달라질 수 있어 일괄적으로 판단하기 어렵다.
  - 공정성과 편향을 추상적인 원칙이 아니라 측정 가능한 평가 기준으로 바꾸는 방법을 더 학습해야 한다.
  - 짧은 기간에 많은 내용을 학습해 각 기술이 언제 필요한지와 실제 구현 절차가 아직 완전히 정리되지 않았다.
3. **액션 플랜**
  - 앞으로 진행할 AI 프로젝트마다 데이터 출처, 이용 조건, 개인정보 포함 여부와 예상되는 편향을 점검하는 체크리스트를 작성한다.
  - 모델의 정확도뿐 아니라 실패 사례, 한계와 사람의 검토가 필요한 조건을 함께 기록한다.
  - Python, NumPy와 Pandas부터 다시 복습하고, 이후 머신러닝과 생성형 AI 내용을 작은 실습 단위로 재구성한다.
  - 이번 과정에서 관심이 생긴 RAG 또는 AI Agent 주제 하나를 선택해 작게 동작하는 개인 프로젝트로 구현한다.
4. **함께 나누고 싶은 점**
  - Responsible AI는 개발을 방해하는 규제가 아니라, 실제 사용자가 안심하고 사용할 수 있는 서비스를 만들기 위한 기본 설계 조건이다.
